# Workflow Editor Plan

## 1. 项目目标

基于现有成品流程图 HTML 风格，开发一个浏览器内可用的流程图编辑器，用于创建横向泳道式流程图，并导出为独立可展示的 HTML 文件。

当前参考样式仅来自以下两个文件：

- `knowledge_creation.html`
- `knowledge_consumption.html`

编辑器第一版聚焦以下核心能力：

- 创建横向泳道式流程图
- 新增、删除、编辑泳道
- 新增、删除、编辑节点
- 拖拽节点位置
- 拖曳调整节点宽度
- 自动计算节点之间的连线
- 切换连线强调状态：灰色 / 主题色
- 配置整体页面主题
- 导出 `html`
- 导出 / 导入 `json`
- 编辑器 UI 支持中文 / 英文切换

## 2. 已确认范围

### 2.1 页面与泳道

- 流程图为横向泳道式布局
- 默认创建 1 个泳道
- 用户可新增泳道
- 用户可删除泳道
- 泳道支持编辑主标题和附标题
- 泳道宽度始终铺满页面画布
- 泳道高度根据泳道数量自动均分

### 2.2 节点

- 用户可新增节点
- 节点可拖拽移动
- 节点可编辑标题、描述、标签
- 节点支持不同视觉类型
- 节点支持拖曳改变宽度
- 节点高度根据内容自动增长
- 节点所属泳道在拖拽跨区时自动更新

### 2.3 连线

- 连线自动生成
- 连线起点和终点总是节点边的中点
- 连线不提供手工编辑控制点
- 连线可切换为灰色或主题色

### 2.4 文件能力

- 可导出独立 `html`
- 可导出 `json`
- 可导入 `json`

### 2.5 语言与主题

- 编辑器界面支持中文 / 英文双语切换
- 导出内容按用户输入原样输出，不做自动翻译
- 支持定义整体页面主题
- 节点与连线强调色需与整体主题协调

## 3. 第一版不做的内容

- 自动智能排版
- 自由绘制折线或手工调整贝塞尔控制点
- 多人协作编辑
- 云端存储
- 版本历史
- 多选批量编辑
- 复杂分组与嵌套容器
- 非横向泳道布局

## 4. 推荐技术方案

### 4.1 工程形态

- `Vite + React + TypeScript`
- 纯前端应用，无后端依赖
- 本地运行和本地导出

### 4.2 渲染方式

- 节点和泳道使用 HTML + CSS 渲染
- 连线使用 SVG 渲染
- 编辑态与导出态共享同一份图数据结构
- 导出 HTML 为单文件，内联样式和静态内容

### 4.3 设计原则

- 尽量复用现有成品的视觉语言
- 以静态导出质量优先，而非通用流程图库能力优先
- 用最小可行数据模型支撑后续扩展

## 6. 数据模型

```ts
export type Locale = "zh-CN" | "en-US"

export type Diagram = {
  meta: {
    title: string
    locale: Locale
    version: string
  }
  theme: Theme
  lanes: Lane[]
  nodes: Node[]
  edges: Edge[]
}

export type Theme = {
  name: string
  bgPrimary: string
  textPrimary: string
  textMuted: string
  accent: string
  accentDeep: string
  accentSoft: string
  lineSoft: string
  boardBackground: string
  laneBackground: string
}

export type Lane = {
  id: string
  title: string
  subtitle: string
  order: number
}

export type NodeType = "default" | "agent" | "shared" | "output"

export type Node = {
  id: string
  laneId: string
  type: NodeType
  title: string
  description: string
  tag: string
  x: number
  y: number
  width: number
  height: number
}

export type EdgeEmphasis = "soft" | "theme"

export type Edge = {
  id: string
  fromNodeId: string
  toNodeId: string
  emphasis: EdgeEmphasis
}
```

### 6.1 坐标与尺寸约定

- 画布内部采用固定设计坐标系，例如 `1600 x 900`
- `x`、`y`、`width`、`height` 建议统一用百分比保存
- 渲染时换算为当前画布像素尺寸
- 导出 HTML 时同样按百分比定位，保证响应式一致性

## 8. 核心交互规则

### 8.1 泳道规则

- 每次新增或删除泳道后，重新计算全部泳道高度
- 泳道顺序决定纵向排列顺序
- 节点始终归属某一个泳道

### 8.2 节点拖拽规则

- 节点只能在画布内移动
- 节点拖动过程中实时更新坐标
- 节点跨泳道时，自动更新 `laneId`
- 节点应被约束在所属泳道垂直范围内

### 8.3 节点宽度调整规则

- 节点左右边缘提供宽度调整手柄
- 最小宽度限制，避免内容完全挤压
- 最大宽度限制，避免超出泳道或画布边界
- 宽度变化后，节点高度重算，连线路径同步更新

### 8.4 连线生成规则

- 起点和终点总是节点边的中点
- 根据节点相对位置自动选择最合理的出边和入边
- 左右关系明显时，优先左右边连线
- 上下关系明显时，优先上下边连线
- 连线使用平滑曲线，不允许用户手工拖动路径

### 8.5 选中与编辑规则

- 单击选中节点 / 连线 / 泳道
- 双击节点可进入内容编辑
- 右侧属性面板始终与当前选中对象同步

## 9. 视觉风格保留点

导出 HTML 需尽量保留现有成品的以下风格：

- 红白主色调
- 背景径向渐变
- 网格与斜向纹理背景
- 半透明 `board` 容器
- 泳道淡色区块
- 节点卡片双层边框感
- serif 标题字体风格
- mono 标签字体风格
- SVG 虚线箭头连线
- `clamp()` 驱动的响应式尺寸

## 11. 导入导出方案

### 11.1 导出 JSON

- 保存完整图数据
- 保存当前语言设置
- 保存当前主题配置
- 用于后续重新导入编辑

### 11.2 导入 JSON

- 校验版本号和基础字段
- 导入失败时给出明确错误提示
- 成功导入后完整恢复编辑状态

### 11.3 导出 HTML

- 生成单文件 HTML
- 内联 CSS
- 根据当前图数据输出静态 DOM 和 SVG
- 导出结果不依赖 React 运行时
- 在浏览器中直接双击打开即可预览

## 12. 核心技术点

### 12.1 坐标换算

- 屏幕像素坐标与画布设计坐标之间要有统一换算逻辑
- 节点拖拽、宽度调整、连线锚点都依赖该逻辑

### 12.2 文本引起的布局变化

- 标题和描述长度会影响节点高度
- 高度变化后必须重算连线终点坐标

### 12.3 连线路径稳定性

- 缩放窗口后连线必须与节点边中点保持一致
- 导出 HTML 后仍需保持路径一致

### 12.4 主题派生色

- 强调色不能脱离整体主题
- 建议从主色自动派生浅色、深色、连线色、背景光晕色

## 14. 删除泳道后的建议策略

默认建议采用以下规则：

- 如果删除的泳道中存在节点，则将这些节点自动迁移到相邻泳道
- 优先迁移到上方泳道
- 如果不存在上方泳道，则迁移到下方泳道
- 如果当前仅剩 1 个泳道，则禁止删除

该策略实现简单，且能避免误删节点。

## 18. 下一步执行建议

如果进入开发阶段，建议先落地最小可用版本：

1. 建立工程骨架
2. 完成单泳道 + 节点拖拽 + 宽度调整
3. 接入自动连线
4. 接入右侧属性编辑
5. 接入 JSON / HTML 导出

达到这个阶段后，再进行主题细化和双语补全，效率最高。
